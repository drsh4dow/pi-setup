### Autopilot-full

**You own each PR and its verdict, never its code. You carry every PR from build to merge through leaf delegates, and nothing merges until your swarm, which never wrote the code, has proven the code that lands.**

A verdict covers one patch and green CI covers one head. Step 4 runs a full swarm once, and again only for a major change. The patch-id rule in `playbooks/shipping.md` can carry a lane's result, and every new head needs its own green CI.

1. **The operator's gates come first.** The grant covers only the queue's items, so items the operator names as theirs and PRs outside the queue stop at merge-ready. A request to state the plan is not a go.
2. **Run each PR yourself through delegates, and keep its work where a replacement can find it.** Resolve the forge once for the program. GitHub CLI (`gh`) is the default. If `command -v origin` succeeds and Origin can resolve the repository, use `origin pr` for every PR operation. Otherwise stay on `gh` and record the fallback. Never require Graphite (`gt`). Each PR gets its own git worktree, with its own ports and state. A code delegate in the PR's playbook role builds there and pushes. You open the PR per `playbooks/opening-a-pr.md`, prove the change on the real artifact through verifier delegates, babysit to green per `playbooks/babysit.md`, and merge once steps 4 and 5 clear it. Every agent in the run is a leaf you spawned, so `bg_list` shows all of them.

   Open the PR early so CI and bots run alongside the work. The code is ready only after the slop-strip (the [`deslop`](../../prompts/deslop.md) prompt, read and applied) and the `/skill:no-comments` pass, so the full swarm runs on finished code. Then rebase onto current trunk and record the code-ready head in the trail before self-proof, so verification runs on the base the patch lands on. A conflict goes to a delegate. Record every later head, and merge-ready once self-proof, CI, and babysit are done. Fix rounds stay on that base unless trunk conflicts or breaks CI, because each rebase restarts CI. Run the repo's checks for the touched paths on the committed head before the code-ready push and before a later push that needs a verifier.

   Assume any agent dies, you included. Soon after starting, start a decision trail in the root agent's store (path in the system prompt) per the **show-me-your-work** skill. Each code delegate pushes after every unit worth keeping. Record each subagent's id, PR, state, and a stuck-after runtime from past runs of its kind in that store, so a replacement can probe it. Force-push only a branch of this run, with `--force-with-lease` pinned to the SHA you last pushed or took over. On any push this run did not make, stop that PR and park it as an operator gate.
3. **Run the PRs in parallel off trunk, never stacked,** so each PR lands on its own.
4. **Swarm-verify once.** A full swarm runs once, at the code-ready head. Another full swarm runs only for new behavior, a redesign, or a large new diff. A rebase, a merge-conflict resolution, or a minor fix gets a single verifier at the new head. Fan out independent verifiers at the code-ready SHA per the **swarm** skill. They re-run the gates, prove the load-bearing behavior live on the real surface through its control skill (such as the `agent-browser` skill, or the `background-terminals` skill with tmux for a TUI) or a named driver, and audit the diff. One live lane is the regression lane against trunk. It runs the trunk behavior the diff touches, error paths included, on trunk and on the head, and reports every difference the PR's plan does not ask for. The verdict is not clean without the live lane, or before you audit the merge-ready receipts, because no lane trusts a claim it has not checked.

   Send every proven finding, whatever a lane labeled it, to a fresh code delegate for that PR in one fix-forward, with a red test across every site with the same defect. A defect trunk shows without the PR is recorded against trunk and does not gate the PR, but one the PR copies or newly reaches is the PR's own. Never push a fix yourself, because each branch has one writer at a time, its code delegate. Replace a stuck delegate instead.
5. **Merge only what you verified, tested on the trunk it lands on.** Green CI alone never authorizes a merge. Once the swarm's lanes have started, merge prep rebases onto current trunk, records the new head, and waits for green CI.

   Right before merging, fetch trunk and ask whether its changes can affect the patch, because rebasing for every trunk move never ends. Rebase and wait for CI when the code that would land was never tested, as with a conflict, a file both sides changed, or a change to which checks run for the PR. A lockfile both sides changed needs no rebase when a frozen install passes on the merge result and the packages the PR changes resolve there as on the head, because that install tests the lockfile that would land, and a failing install means the rebase must repair it. When trunk changed a caller of the patch or something the patch depends on, such as code it calls or a dependency version, run the patch's checks on the merge result and merge on a pass. Otherwise merge. If trunk would force a third rebase past merge prep, hold that PR and sequence the colliding work.
6. **Countersign every loosened gate.** Anything that loosens a gate, such as a raised budget or an allowlist entry, needs a proof from a verifier that never wrote the change, then your fresh countersign in the trail, because the agent that wrote the change is the one who wants green. Under a grant that covers approvals, that countersign is the approval, and its trail row points at the verifier's proof for a lane to check. A disabled or soft-failed check always comes out, because it stops guarding every case. Never give or bypass an approval the forge enforces, because no countersign covers it.

   On the operator's go, arm a `sleep 3600` background terminal, rearmed after each tick, to audit until no delegated work is left, because long runs drift and agents stall silently. Each tick re-reads this playbook from trunk and fixes drift, such as an unrecorded head or agent, by recording it, because drift is a gap in the record, not a stall. It probes every agent in `bg_list` and judges each by its side effects, because status text and summaries can hide a stuck agent. An agent is stuck when it errors, cannot start turns, or shows nothing new past its stuck-after runtime, and so is a code delegate that has not pushed by the first tick. Replace a stuck agent at once, without waiting for its stop to land. A tick that changed something for the operator ends by catching them up per the **ketchup** skill, and one that changed nothing stays quiet.
7. **Stand down at once on the operator's stop.** Stop every running delegate with `bg_kill`, record each one's branch and last pushed SHA in the trail, and write nothing more until the operator releases the hold.

**Reply:** catch the operator up per the **ketchup** skill, covering each PR's state and verdict, what merged, countersigns and why, and open operator gates, with links to each PR and the trails.
