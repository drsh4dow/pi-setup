### Worktree cleanup

1. Snapshot and audit. Record `df -h /`, then run `scripts/worktree-audit.sh [-b <pr-base-ref>] [repo-path]` (principle-build-the-lever). Without `-b` it checks `MERGED` against `origin/HEAD`, so pass `-b origin/<branch>` when PRs target another branch. It reads paths from `git worktree list`, never hand-typed, since a hand-typed `myrepo/worktrees/x` misses one that lives under `~/.local/state/pi-agent/` (principle-encode-lessons-in-structure). It classifies each worktree by size, age, merge state, uncommitted work, PR state, the newest Pi session that touched it, and the live processes whose working directory is inside it, then suggests a bucket. A live process holds its worktree as `hold-in-use`, and your own shell counts, so run the script from outside every worktree. `LIVE` sees only your own user's processes. Run it once for each repository that has worktrees.
2. The bucket is advice, not permission. The sessions still in use are the real artifact (principle-prove-it-works). Build that set from the `LIVE` column, your own `bg_list`, and the sessions the user names, and cross-check every candidate. A worktree that no process uses today can still belong to a session the user plans to resume, so the user's set wins.
3. Verify usage before deleting. For every `verify-recent-chat` row, or anything you doubt, fan subagents out to read the session files and report whether the session is ongoing and which worktrees it touches (principle-guard-the-context-window, session files are bulk). A session spawns arena, swarm, and repro worktrees for its subagents, and those are in use even when their names never appear in its messages. Pick each subagent's reasoning level for the job, per the system prompt's Subagents section.
4. Pause on irreversible loss. `wip:N` is N tracked uncommitted edits. Show the diff and get a decision first, since removing a clean worktree is recoverable from its branch but uncommitted work is gone. `scratch:N` is untracked throwaway, safe to drop, but name the files. A worktree that this session did not create is an artifact you don't own, so present the confirmed set and wait for the user's go before step 5, per the system prompt's Autonomy section.
5. Prune the confirmed set. Per path, `git worktree remove --force <path>`. If the dir survives on ignored build artifacts, `rm -rf` it, then `git worktree prune`. Branch refs survive, so no commits are lost. Confirm with `df -h /` and re-list.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (in use by which session or process, or uncommitted work).
