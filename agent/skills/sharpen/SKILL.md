---
name: sharpen
description: "Sharpen a task before starting: the expert approach, what the user is really after, and the right level of specification. Use for /skill:sharpen."
---

Before starting, ask how a top expert would approach this task (their raw sources, their real methods, an outside check that the result is right), what the user is really after, and whether the task is over- or underspecified. Loosen constraints that don't serve the goal as readily as you add ones that do, and leave choices that are the user's to make open instead of deciding them. Fold in only what makes the work better, not bigger, but always keep one outside check that the result is right. Then do the work the request scopes, without narrating this framing. Don't hand back a rewritten prompt.

The user's choices and the risks grounding surfaced go in the reply as plain questions and findings. Start no work that depends on them. When the input is a new project or an idea with no done criterion, the work is the sharpened framing: the done criterion, the open choices, and the risks. Then end the turn.
